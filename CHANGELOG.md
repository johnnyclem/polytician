# Changelog

All notable changes to this project are documented here. The format follows
[Keep a Changelog](https://keepachangelog.com/en/1.1.0/), and the project uses
[Semantic Versioning](https://semver.org/).

## [3.0.0] - Unreleased

3.0 makes the guarantees the 2.x README claimed hold (atomic versioned writes, filtered search, namespaces, real and restorable encrypted backups, a working deployment), removes what never worked, and adds an MCP Streamable HTTP transport, typed tool results, provenance and an OpenAPPA battery. `POLY-NN` ids refer to the findings of the suite 1.0 audit.

Each change is listed once. Everything under **Removed**, and every **Security** entry marked *Breaking*, is a breaking change too. Upgrade steps for all of them are in [MIGRATION.md](MIGRATION.md).

### Breaking

**Runtime and storage**

- **Node.js 22 or newer** (POLY-31). `engines.node` is `>=22` (Node 20 reached end of life in April 2026); CI runs Node 22 and 24, and the Docker image uses `node:22-bookworm-slim`.
- **`@huggingface/transformers` 4.x replaces `@xenova/transformers` 2.x** (POLY-31). The default model (`Xenova/all-MiniLM-L6-v2`, quantized `q8`) is unchanged. `POLYTICIAN_EMBEDDING_MODEL` must name a model `@huggingface/transformers` can load.
- **An embedding model must produce 384-dimensional vectors** (POLY-27). 2.x silently truncated a larger model's output to 384 components; 3.0 fails the embedding with an error naming both sizes.
- **Each vector records its embedding model, and search refuses to mix models** (POLY-27). `concepts.embedding_model` holds the configured model when the vector was written. A search over namespaces holding vectors from another model fails with `EMBEDDING_MODEL_MISMATCH` (in 2.x, changing `POLYTICIAN_EMBEDDING_MODEL` silently produced meaningless rankings); the new `reembed_concepts` tool re-derives them. Vectors from 2.x are labelled with the model configured on the first 3.0 start.
- **The first start migrates the database in place, and 2.x cannot open it afterwards** (POLY-05, POLY-14, POLY-15, POLY-27). SQLite rebuilds `concept_vectors` (vec0) from `concepts.embedding` with a `namespace` partition key and cosine distance. Postgres drops 2.x's IVFFlat (`vector_l2_ops`, `lists = 100`) index, which was built on an empty table and gave very low recall, and creates `hnsw (embedding vector_cosine_ops)` under an advisory lock (`schema_version = 3` in `metadata`); this needs pgvector ≥ 0.5. Both add the `provenance`, `assertion_status`, `ledger_ref` and `embedding_model` columns (with a partial index on `(namespace, embedding_model)`), label existing vectors once (`legacy_vectors_labelled` in `metadata`), and clear stored embeddings that could never be searched (wrong length, non-finite or all zero, as left by a failed 2.x save).

**Tool contract**

- **Typed tool results.** Every tool declares an `outputSchema` and returns its result as `structuredContent` (validated against that schema before it is sent), with the same JSON in `content[0].text`. `search_concepts` therefore returns `{ "results": [...] }` instead of a bare array (MCP structured content must be an object).
- **`search_concepts` returns `score`, not `distance`** (POLY-05, POLY-14). `score = (1 + cosine similarity) / 2`, in `[0, 1]`, higher is better. Results are ordered by score, and ties by id. The L2 `distance` field is gone. Both backends now rank by cosine distance: sqlite-vec with `distance_metric=cosine`, pgvector with `<=>`.
- **Every tool error carries a code.** Errors are `{ "error", "code" }` with `isError: true` and no `structuredContent`. Arguments that fail a tool's input schema are `VALIDATION_ERROR` instead of plain text (an unknown tool name is `NOT_FOUND`), AgentVault failures in the `vault_*` tools are `UPSTREAM_ERROR`, and any other unexpected failure is `INTERNAL_ERROR`.
- **Strict tool input schemas** (POLY-10). Every tool rejects unknown arguments with a validation error instead of silently dropping them. In 2.x an AgentVault enricher call such as `{ content, metadata }` was stored as an empty concept.
- **A new concept needs at least one representation** (POLY-10). `save_concept` (and the service) reject a create without `markdown`, `thoughtform` or `embedding` with `VALIDATION_ERROR`.
- **`thoughtform` is validated** (POLY-29). It must be the native ThoughtForm shape or a PolyVault v1 ThoughtForm; free-form JSON is rejected. It was `z.any()`, and conversions then crashed with `TypeError`.
- **Embeddings are validated** (POLY-15). Exactly 384 components, all finite and float32-representable, and not all zero. Wrong-dimension vectors used to leave a persisted concept with a corrupt embedding.
- **Input size caps** on every tool: markdown ≤ 1,000,000 characters, thoughtform ≤ 2,000,000 characters of JSON, ≤ 64 tags of ≤ 128 characters, ≤ 500 concepts per batch, query/`embed_text` text ≤ 100,000 characters. Namespaces must match `^[A-Za-z0-9][A-Za-z0-9._:-]{0,63}$`.
- **`expectedVersion` is enforced atomically** (POLY-02). It is checked in the same `UPDATE ... WHERE version = ?` that writes, so of two concurrent writers holding the same version exactly one succeeds and the other gets `VERSION_CONFLICT`. In 2.x both were told they won and one edit was lost. Two concurrent creates of one id now become a create plus an update instead of a raw `UNIQUE` error.
- **Conversions never overwrite authored content without `overwrite: true`** (POLY-16). `convert_concept` fails with `OVERWRITE_REFUSED` if the target representation was written by a caller or imported (provenance origin `user` or `import`, or none recorded). Replacing a previously derived or LLM-made representation is still allowed. With an LLM, both `vector → *` conversions use neighbours from the concept's own namespace only.
- **`save_concept` and `batch_save_concepts` auto-embed by default** (POLY-33). When no `embedding` is passed, the vector is derived from the markdown (else the thoughtform text), so saved concepts are searchable. Opt out with `autoEmbed: false`. `batch_save_concepts` previously defaulted to `false`.
- **`batch_save_concepts` is atomic** (POLY-32). All entries are saved, or none are. It takes `namespace` for the whole batch, and entries accept `expectedVersion`.
- **`get_stats` / `health_check` count one namespace** (default `"default"`), as documented, instead of all namespaces when `namespace` was omitted.
- **`search_concepts` requires exactly one of `query` or `vector`.**

**Backups and AgentVault**

- **One backup format: versioned JSONL** (POLY-01, POLY-22): `polytician-backup`, format version 1, written and read by `export_backup`/`import_backup`, the auto-backup and `agentvault-sync backup`/`restore`. It carries vectors with the embedding model id, and tags, thoughtforms, provenance, assertion status and ledger reference as JSON values, plus a footer checksum. The three 2.x formats (the `agentvault_backup` bundle, the auto-backup's `backup-*.json` with tags and thoughtforms as JSON strings and no vectors, and the CLI's JSON) are no longer read or written.
- **Auto-backup is off by default** (POLY-23) and keeps the newest `POLYTICIAN_BACKUP_RETAIN` (default 10) files. In 2.x it ran every 50 saves with no rotation. `POLYTICIAN_BACKUP_THRESHOLD=0` now disables it (2.x read `0` as 50), and a non-numeric value is a startup error. A burst of saves that crosses the threshold writes one backup.
- **`agentvault-sync backup`** without `--namespace` exports every namespace (POLY-04; 2.x exported only `default` and labelled the file `all`), writes JSONL to `<dataDir>/backups` unless `--out` is given, and honours `--encrypt`. `restore` reads the new format, keeps newer local copies unless `--on-conflict overwrite`, and exits non-zero on errors. `sync` pushes every namespace when `--namespace` is omitted.
- **`vault_memory_pull` is last-write-wins** (POLY-21). An entry replaces a local concept only when its `updatedAt` is newer, entries without `updatedAt` never replace one, entries recorded for another namespace are skipped, and ids must be UUIDs. Skipped entries are reported (`local-newer`, `other-namespace`, `invalid-id`, ...). Pulled concepts are embedded. The startup/periodic pull shares this code and writes each entry into the namespace recorded with it. `vault_memory_push` records the namespace and version with each entry.
- **PolyVault is documented as experimental and library-only** (no shipped command or tool calls it). Its library API changed:
  - Encrypted payloads are stored as `nonce || ciphertext || tag` with AAD `polyvault/1:<bundleId>:<commitId>` (POLY-11). `RestoreOptions.decryptionNonce` is removed; restore reads each commit's nonce from its payload. Encrypted commits written by 2.x cannot be restored by any version, because their nonce was never stored.
  - `runBackup` rejects a ThoughtForm whose `metadata.contentHash` does not equal `computeContentHash()` of its content (exit 2), and the dedupe key covers each ThoughtForm's id, `updatedAtMs` and content hash (POLY-13). `resolveConflict` treats two ThoughtForms as identical only if their content is equal, not just their `contentHash`.
  - Rebase is driven by commit order (POLY-12): `rebase()` takes `remoteCommits` (`{ commitId, createdAtMs, thoughtforms }`) and `lastApplied` (a commit cursor) instead of `remoteForms`, `localBaseUpdatedAtMs` and `observedRemoteMaxUpdatedAtMs`, and `runRebase` reads remote commits and stores `lastApplied` in its state file.

**Deployment**

- **Docker, Compose and Kubernetes run the HTTP transport on port 8788** (POLY-08, POLY-09, POLY-25). The image serves MCP over HTTP with its data in `/data`. `docker-compose.yml` runs one Polytician node and requires `POSTGRES_PASSWORD` and `POLYTICIAN_HTTP_TOKEN` (no `changeme` default); it publishes only `127.0.0.1:8788`, and Postgres is no longer published on the host. `k8s/postgres.yml` no longer contains a Secret (create it yourself), and the polytician Service and probes moved to port 8788.
- **`/health` reports less** (POLY-07, POLY-26). The body has `database` and `vector_index` checks with `ok`/`error` only; details are logged. The `sidecar` check and raw error messages are gone.

**Library API (`ConceptService`, `DatabaseAdapter`)**

- `search()` results carry `score` and `assertionStatus`. `search()` options take `namespaces: string[] | '*'` instead of `crossNamespace`, and `assertionStatus`. `read()`/`delete()` take `{ namespace }`. `save()` takes `autoEmbed`/`source`/`provenance`/`overwrite`/`assertionStatus`/`ledgerRef`. Adapters implement `applyWrites()`, `countForeignVectors()`, `findForeignVectors()` and `labelLegacyVectors()`; rows carry `embedding_model`, `provenance`, `assertion_status` and `ledger_ref`; `vectorSearch(query, k, filter)`/`upsertVector(id, namespace, embedding)` changed signature; and `vectorSearch`/`listConcepts` filter by `assertionStatus`. `SummarizeOptions.neighborDistances` became `neighborScores`. `PolyticianConfig` lost `sidecarUrl` and `distributed`; `healthPort` is `number | null`, and `healthHost` and `http` were added.

### Security

- **Breaking. Config is read only from trusted places** (POLY-06). Environment variables, `~/.polytician/config.json`, or `--config <path>`. `.polytician.json` in the working directory (which MCP clients set to the opened project) and `~/.polytician.json` are no longer read: a cloned repository could redirect AgentVault traffic and sync memories to an attacker. A config file that exists but is invalid, and an invalid `agentVault` block, are now startup errors instead of being ignored.
- **Breaking. `${VAR}` expansion is limited to `POLYTICIAN_*` variables** (POLY-06) in config-file values (`agentVault.apiToken`, `archival.arweaveJwk`); a reference to any other variable is an error. `POLYTICIAN_AV_API_TOKEN` is used literally. In 2.x `"apiToken": "${AWS_SECRET_ACCESS_KEY}"` sent that secret as the bearer token.
- **Breaking. AgentVault `apiBaseUrl` must be `https`** (POLY-06); plain `http` is accepted only for `localhost`, `127.0.0.1` and `[::1]`.
- **Breaking. Encryption is real and fails closed** (POLY-03). `POLYTICIAN_ENCRYPT` / `--encrypt` used to be a silent no-op (every backup was plaintext). Backups are now encrypted with AES-256-GCM under a key from `POLYTICIAN_BACKUP_KEY` or an owner-only key file (`POLYTICIAN_BACKUP_KEY_FILE`, default `<dataDir>/backup.key`). With `POLYTICIAN_ENCRYPT` set, every backup writer encrypts, a plaintext export is refused, and a missing key is an error (`CONFIG_ERROR`) rather than a plaintext file; the server refuses to start without a key.
- **Breaking. Files are owner-only** (POLY-23). Backup files are mode `600` in a `700` directory, and the SQLite database file is set to mode `600` on start (a new data directory is created `700`). 2.x wrote world-readable auto-backups.
- **Breaking. Namespaces are enforced on id-based tools** (POLY-17). `read_concept`, `delete_concept`, `convert_concept`, `vault_memory_push` and `vault_archive_concept` take `namespace` (default `"default"`), and a concept in another namespace is `NOT_FOUND`. `save_concept` refuses to update a concept that lives in another namespace (`NAMESPACE_DENIED`), and `import_backup` skips one (`other-namespace`). `vault_memory_pull` writes into one namespace and reports entries it had to skip.
- **Breaking. `crossNamespace` search requires operator opt-in** (POLY-17). It is refused (`NAMESPACE_DENIED`) unless `POLYTICIAN_NAMESPACES` is set, and then spans exactly the allowlisted namespaces (all of them for `*`). It is also refused together with `namespace` (`VALIDATION_ERROR`): a cross-namespace search used to ignore `namespace`, so a policy keyed on the `namespace` argument could be bypassed. The allowlist does not authenticate callers; the README's "Namespaces" section states the boundary.
- **Breaking. Arweave archival is opt-in, filtered and encrypted** (POLY-19). `archival.enabled` requires a non-empty `archival.tagFilter` (an empty filter used to archive every concept, in plaintext, permanently and publicly) and a backup key; concepts are encrypted with that key before upload, and their tags and namespace are no longer published. `vault_archive_concept` is registered only when archival is enabled, applies the same tag filter and encryption, archives each version once, and carries `openWorldHint` annotations. In 2.x it always failed because it never loaded the wallet.
- **Breaking. No implicit AgentVault inference** (POLY-24). With AgentVault configured and `llm.provider` `none`, 2.x routed every LLM conversion (with neighbouring concepts' text) to AgentVault's inference chain. It now happens only with `POLYTICIAN_LLM_PROVIDER=agentvault`.
- **Breaking. AgentVault requests that change state are not retried** (POLY-18). Memory commits, tombstones and archival uploads are sent once: a timed-out POST may still have been applied, so a retry could duplicate a permanent upload and resend the wallet. GETs and inference are still retried. Archival uploads use `archival.timeoutMs` (default 120 s) instead of the inference timeout. `AVHttpClient.get/post/delete` take `RequestOptions` instead of a timeout number.
- **Breaking. The health server is off by default and binds `127.0.0.1`** (POLY-07). In stdio mode `/health` is served only when `POLYTICIAN_HEALTH_PORT` is set, on `POLYTICIAN_HEALTH_HOST` (default `127.0.0.1`). 2.x always listened on `0.0.0.0:8787`, which also collided with stenographer's REST daemon. The default port, when enabled, is 8788. A `POLYTICIAN_HEALTH_PORT` that is not a port number is a startup error (2.x fell back to 8787).
- **Breaking. Hardened deployment files** (POLY-25): no default database password, Postgres not published on the host, no committed Kubernetes credentials, non-root pods with a read-only root filesystem, no capabilities and the `RuntimeDefault` seccomp profile, and a NetworkPolicy. The base and Postgres images are pinned by digest.
- `vault_restore` read any file on disk through its `path` argument and echoed the first bytes of non-JSON files in its error (POLY-20). It is removed (see Removed); `import_backup` reads only files inside `<dataDir>/backups`, by name, resolved through `realpath` so symlinks out are refused, and its errors name line numbers and fields, never file content.
- The Python sidecar listened unauthenticated on `0.0.0.0:5001` with no request-size limit (POLY-26). It is removed (see Removed).
- Production dependency advisories cleared (POLY-31): 2.x pulled in a critical protobufjs advisory (via onnxruntime-web) and vulnerable sharp/libvips builds through `@xenova/transformers`, and the MCP SDK moved to 1.31. `npm audit --omit=dev --audit-level=high` is clean, and the CI and publish audit gates now fail on production advisories (the CI audit used to end in `|| true`).

### Removed

- **`agentvault_backup`** (POLY-01). It reported success and a SHA-256 but wrote nothing anywhere, ignored `POLYTICIAN_ENCRYPT`, and covered only one namespace. Use `export_backup`, `import_backup` and `list_backups`.
- **`vault_restore`** (POLY-20): inline bundles and arbitrary paths. Use `import_backup` with a file name in `<dataDir>/backups`.
- **Reading 2.x backup files** (POLY-22): the `agentvault_backup` bundle, auto-backup `backup-*.json` and the CLI's JSON. Restore a 2.x backup with 2.x.
- **The Python sidecar** (POLY-26): `python-sidecar/`, `k8s/sidecar.yml`, the compose `sidecar` service, `POLYTICIAN_SIDECAR_URL`, `src/sidecar/faiss.ts` and `src/lib/polyvault/faiss-client.ts`. Its FAISS index was written but never queried (search has always used sqlite-vec or pgvector). PolyVault's `runRestoreE2E(client, db, options)` lost its `faissClient` argument, the `faissMode` option and the `faiss` result field.
- **`IndexSyncService` and `POLYTICIAN_ASYNC_INDEX_SYNC`** (`distributed.asyncIndexSync`; POLY-02, POLY-15). The vector is now written in the same transaction as its row. The event-driven re-sync ran outside that transaction and could re-insert the vector of a concept deleted in the meantime.
- **The unused `distributed` settings** `POLYTICIAN_NODE_ID`, `POLYTICIAN_EXTERNAL_STATE_URL` and `POLYTICIAN_VECTOR_INDEX_URL` (`distributed.*` in the config file; POLY-08). Nothing read them. The server logs a warning when one is still set.
- **LLM providers `anthropic`, `openai` and `sampling`** (POLY-24), which were never implemented, along with `POLYTICIAN_LLM_MODEL`, `POLYTICIAN_LLM_API_KEY` (`llm.model`, `llm.apiKey`) and `agentVault.secrets.llmApiKey` (and `AgentVaultSecretProvider`), whose only effect was to fill that unread key. `POLYTICIAN_LLM_PROVIDER` accepts `none` or `agentvault`; anything else is a startup error.
- **The non-LLM `vector → markdown` fallback** (POLY-16), which pasted neighbouring concepts' text (from the `default` namespace, whatever the concept's own namespace was) into the concept's markdown. `vector → markdown` without an LLM provider is now a `CONVERSION_ERROR`.
- **Config files in the working directory and `~/.polytician.json`** (POLY-06); see Security.
- **`encryptBundle` / `decryptBundle`** in `src/storage/thoughtform.ts` (POLY-03), which returned their input unchanged.
- **PolyVault `computeSkewSafeLowerBound`** (POLY-12) and **`RestoreOptions.decryptionNonce`** (POLY-11).

### Added

- **MCP over Streamable HTTP** (POLY-08; `--http` or `POLYTICIAN_TRANSPORT=http`): `POST /mcp` (stateless, so replicas need no session affinity), with `/health` and `/health/live` on the same port (default `127.0.0.1:8788`). Every `/mcp` request needs a bearer token (`POLYTICIAN_HTTP_TOKEN`, or a random token generated into `<dataDir>/http-token` with mode `600`), a `Host` in `POLYTICIAN_HTTP_ALLOWED_HOSTS` (loopback names by default; required when binding elsewhere) and no `Origin` or one in `POLYTICIAN_HTTP_ALLOWED_ORIGINS`. The SDK negotiates MCP protocol revisions up to 2025-11-25. 2.x had only stdio, so its Docker, compose and Kubernetes deployments exposed nothing but `/health`.
- **`export_backup`, `import_backup` and `list_backups`** (POLY-01, POLY-22). `export_backup` writes a file into `<dataDir>/backups` covering every namespace the server serves, `import_backup` verifies a file (checksum, counts, AES-GCM tag) and validates every concept before restoring them all in one transaction with their ids, namespaces, timestamps, vectors and provenance, keeping newer local copies by default, and `list_backups` lists them. `ConceptService.restore(records, { onConflict })` is the library entry point.
- **OpenAPPA battery** (`integrations/openappa/`, pinned to OpenAPPA 0.30.0): contracts for all 20 tools under the canonical ids `mcp/polytician/<tool>`, with namespaces as label compartments. A call that names a namespace is labelled with that namespace's readers, which the bundled `polytician` audience source reads from an operator-written file (`POLYTICIAN_NAMESPACE_READERS`); writes need trusted data the namespace's readers may see; imports and off-box AgentVault calls need review. `npm run appa:check` runs the audience source's tests and, when `appa` is on `PATH`, `appa describe --check` and `appa replay` over the bundled traces (CI runs it without `appa`). `tests/openappa-battery.test.ts` fails when a tool lacks a contract.
- **Provenance per representation** (POLY-16). Each concept's `provenance` maps every representation to `{ origin, derivedFrom?, model?, createdBy?, sources? }`. `origin` is `user` (written by a caller), `derived` (computed without an LLM: the embedding model, the thoughtform→markdown template, the rule-based NLP pipeline), `llm` (an LLM conversion or a saved `vault_infer` answer) or `import` (AgentVault pulls, PolyVault restores, or content a caller declares imported). `model` names the embedding model, NLP pipeline or LLM provider. `save_concept` and `batch_save_concepts` take `source: { origin?: "user" | "import", createdBy?, model? }`; `createdBy` is recorded as the caller gives it and is not authenticated. Backups carry provenance. Representations stored before 3.0 have none recorded and count as authored.
- **Assertion status and ledger reference.** A concept can carry `assertionStatus` (`asserted`, `verified`, `contested`, `retracted`, or null) and `ledgerRef` (the ledger entry it mirrors, up to 512 characters), so stenographer TB/UV entries can be stored with their truth status. Both are set, changed or cleared (`null`) through `save_concept`/`batch_save_concepts`, returned by `read_concept`, `list_concepts` and `search_concepts`, and carried by backups. `search_concepts` and `list_concepts` take an `assertionStatus` filter, applied inside the vector query like the tag filter. Polytician stores the status it is given; it does not check it against the ledger.
- **`reembed_concepts { namespace?, overwrite?, limit? }`** and `ConceptService.reembed()` (POLY-27): re-derive the vectors another embedding model made.
- **MCP tool annotations on every tool** (`readOnlyHint`, `destructiveHint`, `idempotentHint`, `openWorldHint`). `openWorldHint` on the writing tools is true when the operator enabled AgentVault sync push or archival, and on `convert_concept` also when `POLYTICIAN_LLM_PROVIDER=agentvault`; it is always true on the `vault_*` tools.
- **Stable error codes**: `NOT_FOUND`, `VALIDATION_ERROR`, `VERSION_CONFLICT` (with `currentVersion`), `NAMESPACE_DENIED`, `OVERWRITE_REFUSED`, `CONVERSION_ERROR`, `EMBEDDING_MODEL_MISMATCH`, `CONFIG_ERROR` (a call needs configuration the server lacks, such as a backup key), `UPSTREAM_ERROR`, `INTERNAL_ERROR`.
- `POLYTICIAN_NAMESPACES` (or `namespaces` in the config file; POLY-17): the operator allowlist of namespaces a server serves.
- `POLYTICIAN_BACKUP_KEY` / `POLYTICIAN_BACKUP_KEY_FILE` (POLY-03) and `POLYTICIAN_BACKUP_RETAIN` (POLY-23).
- `convert_concept` `overwrite` argument, and `autoEmbed` on `save_concept` (POLY-16, POLY-33).
- `--config <path>` command-line option, and a startup log line naming the AgentVault endpoint and which off-box paths (LLM, sync, archival) are enabled (POLY-06). The startup log also names the Polytician version.
- `openArchive()` in the archival connector decrypts a downloaded Arweave archive with the backup key (POLY-19).
- PolyVault `computeContentHash()` and `withContentHash()` (POLY-13).
- `/health/live` liveness endpoint (POLY-07).
- `k8s/networkpolicy.yml` (only labelled clients reach Polytician, only Polytician reaches Postgres), pod and container `securityContext`, separate readiness (`/health`) and liveness (`/health/live`) probes (POLY-25).
- `scripts/smoke-http.mjs` and a CI job that builds the Docker image and runs save → search over HTTP against it, with the real embedding model (POLY-09, POLY-35).
- Postgres adapter test suite (`tests/postgres-adapter.test.ts`, run with `POLYTICIAN_TEST_POSTGRES_URL`) and a CI job against `pgvector/pgvector` (POLY-14, POLY-35).
- Contract tests replaying AgentVault's `polytician-enricher` calls (`tests/mcp-contract.test.ts`), and the correct contract in the README (POLY-10).

### Fixed

- Namespace- and tag-filtered search no longer post-filters a global top-k (POLY-05). The filters run inside the KNN query: the vec0 namespace partition key and a candidate-id constraint on sqlite-vec, SQL `WHERE` with HNSW iterative scan (or exact scan on pgvector < 0.8) on Postgres. A crowded namespace can no longer hide another namespace's matches.
- Postgres searches return up to `k` results beyond the default `hnsw.ef_search` of 40 (POLY-05, POLY-14).
- Saving is atomic (POLY-15): the concept row and its vector are written in one transaction on both backends. A failed vector write no longer leaves a concept that reports a vector but is never found.
- Concurrent tag merges without `expectedVersion` no longer lose tags (POLY-02).
- A backup can be restored (POLY-22): in 2.x the only persisted backups (auto-backups) stored tags and thoughtforms as JSON strings and no vectors, so a restore corrupted tags (a later tag merge produced `["[", "\"", ...]`), double-encoded thoughtforms and left nothing searchable.
- `list_concepts` tag filtering matches tags exactly (POLY-34). `_` and `%` were `LIKE` wildcards, and tags containing `"` never matched.
- `convert_concept` of a PolyVault v1 thoughtform no longer crashes with a `TypeError` on `toFixed`/`slice` (POLY-29).
- Saved markdown is searchable without a separate `convert_concept` (POLY-33); the README's save → search flow used to return nothing.
- A failed embedding-model load (for example the first download while offline) is retried on the next call instead of failing every embedding until restart (POLY-27).
- Rule-based relationship inference (`markdown → thoughtform` with `POLYTICIAN_NLP_PIPELINE=rule-based`) is linear in the text instead of roughly cubic in the number of entities (POLY-28): lines and bullets are separate sentences, only neighbouring mentions are paired, and mentions are found by word lookup (capped at 64 per sentence and 5,000 relationships). A 1,000-entity note took about 5 s and blocked the server; 10,000 entities now take about 0.1 s.
- A second stdio server no longer crashes on `EADDRINUSE` (POLY-07): a taken health port is logged and the MCP server keeps running. The stdio server exits when its client closes stdin; 2.x kept running, holding the database and its port.
- The Docker image starts (POLY-09). 2.x installed with `--ignore-scripts`, so better-sqlite3 and sharp had no native binaries; the image's health check used `curl`, which it does not contain, and now uses `node`.
- PolyVault encrypted backups can be restored (POLY-11; 2.x discarded the AES-GCM nonce), an edit with a stale producer `contentHash` is backed up instead of being reported as a duplicate (POLY-13), and rebase keeps edits from a device that synced late (POLY-12).
- `agentvault-sync` works against a Postgres store.
